## 📐 การวิเคราะห์ระบบ (OOAD)

### 1. ปัญหาเดิมและวัตถุประสงค์
* **ปัญหาเดิม:** การแจ้งซ่อมในโรงเรียนมักใช้เอกสารกระดาษหรือไลน์กลุ่ม ทำให้ข้อมูลสูญหาย ติดตามสถานะงานไม่ได้ ไม่มีประวัติการเปลี่ยนอะไหล่และค่าใช้จ่าย การมอบหมายงานให้ช่างขาดความโปร่งใส
* **วัตถุประสงค์:** 
  1. สร้างศูนย์กลางการรับแจ้งซ่อมแบบออนไลน์ ตลอด 24 ชม.
  2. ให้ครูและบุคลากรติดตามสถานะงานได้แบบเรียลไทม์ พร้อมระบบแสดงความคิดเห็น
  3. ให้ผู้ดูแลระบบมอบหมายงานแก่ช่างและกำหนดวันเสร็จสิ้นได้อย่างชัดเจน
  4. ให้ช่างซ่อมบันทึกผลงาน ค่าใช้จ่าย และอัปโหลดภาพก่อน-หลังซ่อม
  5. เก็บรวบรวมประวัติเพื่อการบริหารงบประมาณและวิเคราะห์อุปกรณ์ที่เสียบ่อย

### 2. ผังความสัมพันธ์ (Use Cases)
* **Teacher (ผู้แจ้ง):** `สร้างใบแจ้งซ่อม` -> `แนบรูปถ่ายความเสียหาย` -> `ติดตามสถานะ` -> `พิมพ์ใบแจ้งซ่อม A4` -> `พูดคุยในช่องความคิดเห็น`
* **Admin (ผู้ดูแลระบบ):** `ตรวจสอบใบแจ้งซ่อมทั้งหมด` -> `มอบหมายงานให้ช่าง + กำหนด Due Date` -> `จัดการบัญชีผู้ใช้งานและกำหนด Role` -> `ดูแดชบอร์ดสถิติ` -> `ส่งออกข้อมูล CSV`
* **Technician (ช่างซ่อม):** `ดูงานที่ได้รับมอบหมายเท่านั้น` -> `เริ่มดำเนินการซ่อม (Start Repair)` -> `บันทึกปิดงานซ่อม + ระบุผลงาน + ค่าใช้จ่าย + แนบภาพหลังซ่อม`

### 3. Workflow และ State Transitions (Finite State Machine)
```text
[ pending ]  ──( Admin มอบหมายช่าง )──>  [ accepted ]
     │                                         │
     │                               ( ช่างเริ่มดำเนินการ )
     │                                         │
     ▼                                         ▼
(ไม่อนุญาตข้ามขั้น)                       [ in_progress ]
                                               │
                                       ( บันทึกผลซ่อม + ค่าใช้จ่าย )
                                               │
                                               ▼
                                         [ completed ]
```

## 🏛️ หลักการ OOP ในระบบ

1. **Encapsulation (การห่อหุ้ม):**
   * โมเดล `User` ห่อหุ้ม `password_hash` โดยไม่อนุญาตให้เซ็ตค่าดิบ มีเมธอด `set_password()` และ `check_password()` ด้วย Werkzeug PBKDF2
   * โมเดล `RepairRequest` ควบคุมการเปลี่ยนสถานะผ่านเมธอด `assign_to_technician()`, `start_repair()`, และ `complete_repair()` พร้อมตรวจสอบสถานะก่อนหน้า (Invariants Check) ห้ามเปลี่ยนสถานะข้ามขั้น

2. **Abstraction (การซ่อนรายละเอียด):**
   * แยกชั้นการทำงานเป็น **Route Layer** (HTTP/Views) -> **Service Layer** (Business Rules) -> **Repository Layer** (Data Access)
   * ส่วนเรียกใช้งานไม่ต้องทราบคำสั่ง SQL หรือกลไกการคิวรีฐานข้อมูลโดยตรง

3. **Inheritance (การสืบทอดคุณสมบัติ):**
   * คลาส `User` สืบทอดจาก `flask_login.UserMixin` และ `db.Model` เพื่อนำฟังก์ชันตรวจสอบ `is_authenticated`, `is_active` มาใช้งาน
   * ข้อยกเว้นทางธุรกิจสืบทอดจาก Exception พื้นฐาน เช่น `RepairTransitionError` และ `RepairAuthorizationError`

4. **Polymorphism (การพ้องรูป):**
   * คลาสแม่ `BaseReportExporter` มีเมธอดนามธรรม `export()` โดยมีคลาสลูก `CsvReportExporter` และตัวแปลงรูปแบบอื่นทำงานสอดคล้องตามโพลีมอร์ฟิซึม

5. **Composition (การประกอบกันของวัตถุ):**
   * วัตถุ `RepairRequest` 1 รายการ ประกอบไปด้วย:
     - `RepairImage` (ภาพถ่ายก่อน-หลังซ่อม) แบบ One-to-Many
     - `Comment` (ความคิดเห็นประสานงาน) แบบ One-to-Many
     - `RepairStatusHistory` (ประวัติการเปลี่ยนสถานะเพื่อ Audit Trail) แบบ One-to-Many

## 🗄️ โครงสร้างฐานข้อมูล SQLite

ตารางหลัก 5 ตาราง พร้อมเปิดใช้งาน `PRAGMA foreign_keys = ON;`:
1. `users` — บัญชีผู้ใช้, รหัสผ่านแฮช, สิทธิ์ (Role: admin, teacher, technician)
2. `repair_requests` — ใบแจ้งซ่อม, สถานที่, ปัญหา, ความเร่งด่วน, สถานะ, ค่าใช้จ่าย, ผลซ่อม
3. `repair_images` — รูปภาพหลักฐาน (type: before / after)
4. `comments` — ข้อความสอบถามและประสานงาน
5. `repair_status_history` — ประวัติการเปลี่ยนสถานะพร้อมผู้ดำเนินการและเวลา

## 🚀 ขั้นตอนการติดตั้งและเริ่มใช้งาน

### 1. ความต้องการของระบบ
* Python 3.10 หรือใหม่กว่า
* SQLite3

### 2. ขั้นตอนการติดตั้ง
```bash
# 1. โคลนหรือเข้าไปยังโฟลเดอร์โปรเจกต์
cd schoolfix

# 2. สร้าง Virtual Environment
python3 -m venv venv
source venv/bin/activate  # บน Windows ใช้: venv\Scripts\activate

# 3. ติดตั้ง Dependencies
pip install -r requirements.txt

# 4. สร้างและ Seed ฐานข้อมูลเริ่มต้น
python seed_db.py

# 5. รันเซิร์ฟเวอร์ Flask
python app.py
```
เปิดเว็บเบราว์เซอร์ไปที่: `http://localhost:5000`

## 🧪 การรันชุดทดสอบ (Unit Tests)

รันชุดทดสอบทางสถาปัตยกรรม OOP และความปลอดภัย:
```bash
python3 -m unittest tests/test_domain_and_security.py
```

ผลการทดสอบ:
* ตรวจสอบรูปแบบหมายเลขใบแจ้งซ่อม `RP-YYYYMM-XXX`
* ตรวจสอบ State Machine: `pending` -> `accepted` -> `in_progress` -> `completed`
* ตรวจสอบการปฏิเสธการข้ามขั้นตอนโดยไม่ได้รับอนุญาต
* ตรวจสอบความปลอดภัย: ครูไม่สามารถดูงานของผู้อื่น
* ตรวจสอบความปลอดภัย: ช่างไม่สามารถแก้ไขงานที่ไม่ได้มอบหมายให้ตนเอง
* ตรวจสอบความถูกต้องของค่าใช้จ่ายและผลการซ่อม
